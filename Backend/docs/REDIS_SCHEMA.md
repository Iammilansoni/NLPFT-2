# Redis Schema Documentation

## Unified Schema for All Embeddings

All embeddings in Redis use the **same unified schema**, regardless of their source:
- Existing `csv_dataset.csv` embeddings
- User-uploaded CSV files
- Generated datasets from plain English queries

## Redis Index Schema

```python
Index Name: idx:apis
Prefix: api:

Schema Fields:
├── embedding (VectorField)
│   ├── Type: FLOAT32
│   ├── Dimension: 384 (or model dimension)
│   ├── Algorithm: HNSW
│   └── Distance Metric: COSINE
├── intent (TextField)          # API intent name (e.g., "login", "register")
├── slots_json (TextField)       # JSON string of extracted slots/parameters
├── query (TextField)            # Original natural language query
├── hash_id (TextField)          # SHA256 hash of query (for deduplication)
├── api_name (TextField)         # API name (usually same as intent)
├── endpoint (TextField)         # API endpoint URL
├── template_version (NumericField)  # Template version number
├── created_at (TextField)       # ISO timestamp
└── confidence (NumericField)    # Extraction confidence score
```

## Redis Key Format

All embeddings use hash-based keys for deduplication:

```
Key Format: api:{hash_id}
Example: api:a3f5b2c1d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1
```

Where `hash_id` is the SHA256 hash of the query text.

## Data Flow

### 1. Existing csv_dataset.csv Format
**Input CSV:**
```csv
query,api,endpoint,request,response
"login with john","login","/api/login","{\"username\":\"john\"}","{...}"
```

**Converted to Redis Schema:**
```python
{
    "embedding": <384-dim vector bytes>,
    "intent": "login",                    # from 'api' column
    "slots_json": "{\"username\":\"john\"}",  # from 'request' column
    "query": "login with john",
    "hash_id": "a3f5b2c...",            # SHA256 of query
    "api_name": "login",                 # from 'api' column
    "endpoint": "/api/login",
    "template_version": 1,
    "created_at": "2025-01-10T12:00:00Z",
    "confidence": 1.0
}
```

query,intent,slots,api_name,endpoint

## Key Points

1. **Unified Schema**: All embeddings use the same Redis schema regardless of source
2. **Hash-based Keys**: All use `api:{hash_id}` format for automatic deduplication
3. **Field Mapping**: 
   - Old format: `api` → `intent`, `request` → `slots_json`
   - New format: Direct mapping
4. **Automatic Conversion**: `dataset_ingestor.py` handles conversion from both formats
5. **No Overwrites**: Hash-based deduplication ensures existing embeddings are never overwritten

## Search Query

All embeddings are searchable using the same query format:

```python
FT.SEARCH idx:apis "*=>[KNN 5 @embedding $vec AS score]"
```

Where `$vec` is the query embedding vector.

## Benefits of Unified Schema

1. **Consistency**: All data uses the same structure
2. **Compatibility**: Old and new data work together seamlessly
3. **Deduplication**: Hash-based keys prevent duplicates
4. **Searchability**: All embeddings are searchable using the same index
5. **Extensibility**: Easy to add new fields without breaking existing data
